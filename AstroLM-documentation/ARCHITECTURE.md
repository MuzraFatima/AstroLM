# Architecture Specification — NebulaLM v1

## 1. Source-of-truth rule

The resolved runtime configuration file is authoritative for a run. It must be copied into the run directory and checkpoint. Documentation lists the planned baseline and allowed pilot variations; it must never override a saved run configuration.

The implementation must expose one configuration object and a script that prints the resolved configuration and exact parameter count. Hard-coded architectural values outside that object are prohibited.

## 2. Planned baseline

| Field | Planned value |
|---|---:|
| model family | decoder-only transformer |
| layers | 8 |
| attention heads | 8 |
| embedding width | 512 |
| head width | 64 |
| MLP width | 2,048 |
| context length | 256 tokens |
| vocabulary | selected tokenizer; 8,000 is the initial primary candidate |
| norm | pre-LayerNorm |
| activation | exact GELU, non-approximate |
| position representation | learned absolute embeddings |
| weight tying | token embedding and LM output projection share one parameter |
| dropout | 0.10 baseline; 0.20 is the only planned pilot alternative |

At an 8,000-token vocabulary, the expected total is approximately 29.45M parameters under the detailed definition below. Code-generated counts are authoritative.

## 3. Block definition

For input `x`:

1. `x = x + attention(layer_norm_1(x))`
2. `x = x + mlp(layer_norm_2(x))`

Attention uses a single biased QKV projection, scaled dot-product attention, a strict causal mask, an output projection, and configured attention/residual dropout. The implementation may use a PyTorch attention primitive only after equivalence with the project reference implementation is tested; it must not change masking semantics.

The MLP is `Linear(512, 2048) -> GELU -> Linear(2048, 512)` with biases and configured dropout.

The model applies a final LayerNorm and a bias-free LM head tied to the token embedding.

## 4. Embeddings, positions, and masks

- Token and learned positional embeddings are added before the first block.
- Valid positions are `0..255`; inputs longer than 256 must fail clearly or be truncated only by an explicit caller option.
- The causal mask must prevent every query position from attending to future keys.
- If packed examples use segment isolation, the supplied attention mask must additionally prevent cross-document attention. If packing deliberately permits cross-document attention, that decision must be identical in training and evaluation and recorded in the data configuration.
- PAD positions, when present, must not contribute to attention or loss.

## 5. Initialization

- Linear and embedding weights: normal distribution, mean 0, standard deviation 0.02.
- Biases: zero.
- LayerNorm scale: one; LayerNorm bias: zero.
- Residual output projections use standard deviation `0.02 / sqrt(2 * n_layer)`.
- Initialization seed is supplied by configuration and recorded.

Any departure requires a registered experiment.

## 6. Loss

The model predicts token `t+1` from tokens through `t`. Cross-entropy is computed only where the loss mask is one. Reported dataset loss is token-weighted, not an unweighted mean of batch means. The training API must return both summed negative log-likelihood and valid-token count.

## 7. Optimizer parameter groups

- Decay group: matrix-valued learned weights, including the tied token embedding exactly once.
- No-decay group: biases and LayerNorm parameters.
- Every parameter must occur in exactly one group.

The grouping is tested and serialized in run metadata.

## 8. Smaller transformer baseline

The registered neural baseline uses the same tokenizer, context, data, packing, objective, and training-token budget, with 4 layers, 6 heads, and width 384. Its exact parameter count is generated by code and reported; “approximately 10M” is descriptive.

No other architecture comparison is required for v1.

## 9. Deferred features

RoPE/ALiBi, Flash Attention-specific code, KV caching, sparse or mixture-of-experts layers, distributed support, and longer context are deferred. PyTorch kernel optimizations that preserve tested semantics may be enabled as measured implementation options, not research features.
